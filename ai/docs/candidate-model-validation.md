# 후보 군중 계수 모델 적용 가능성 검증

## 1. 검증 목적

SAFY의 혼잡도 분석에 사용할 기본 모델과 고밀도 인파 상황에서 사용할 후보 모델을 결정하기 위해 다음 모델을 비교했다.

- YOLO11n
- P2PNet
- DM-Count

이번 검증은 모델의 최종 정확도를 확정하는 작업이 아니다. 현재 개발 환경에서 모델이 실행 가능한지 확인하고, SAFY 서비스 구조에 적용할 때 필요한 변경 범위와 제약사항을 파악하는 것이 목적이다.

## 2. 검증 환경

- 운영체제: Windows
- Python: 3.11.9
- PyTorch: 2.13.0+cu130
- torchvision: 0.28.0+cu130
- GPU: NVIDIA GeForce RTX 4050 Laptop GPU
- GPU 메모리: 6GB
- YOLO 모델: yolo11n
- P2PNet 가중치: ShanghaiTech Part A
- DM-Count 가중치: UCF-QNRF

측정된 처리시간은 단일 실행 결과다. 입력 이미지 크기, 초기 모델 로딩, GPU 워밍업 및 시스템 상태가 통제되지 않았으므로 모델 간 공식 성능 비교나 운영 FPS로 사용하지 않는다.

## 3. 모델별 출력 차이

| 모델 | 주요 출력 | SAFY 적용 방식 |
| --- | --- | --- |
| YOLO11n | 사람 박스, 중심점, 신뢰도, 사람 수 | 기존 FastAPI 및 C·L 계산에 직접 사용 |
| P2PNet | 사람 머리 위치점, 신뢰도, 사람 수 | 위치점을 정규화해 기존 격자 계산에 사용 가능 |
| DM-Count | 밀도 맵, 전체 추정 인원수 | 밀도 맵을 격자별로 합산하는 별도 계산 규칙 필요 |

## 4. YOLO11n 검증 결과

YOLO11n은 현재 SAFY AI 서버의 기본 모델로 구현되어 있다.

현재 제공하는 값은 다음과 같다.

- 사람 수
- 탐지 신뢰도
- 정규화된 사람 중심점
- 정규화된 사람 박스
- 처리시간
- C·L 혼잡도 계산 입력

버스 이미지에서는 실제 확인 인원 4명에 대해 4명을 탐지했다.

기존 FastAPI 분석 API, 혼잡도 계산, 디버그 시각화 및 이후 개인정보 블러 처리에 필요한 위치 정보를 모두 제공한다.

### 장점

- 현재 프로젝트에 이미 연동되어 있다.
- 희소 인원과 일반적인 거리 이미지에서 안정적으로 동작했다.
- 사람 박스와 중심점을 모두 제공한다.
- 기존 C·L 혼잡도 계산을 그대로 사용할 수 있다.
- 추후 얼굴 및 개인정보 블러 처리와 연결하기 쉽다.
- 현재 Python 및 PyTorch 환경에서 별도의 호환성 수정 없이 실행된다.

### 한계

- 사람이 매우 작거나 서로 심하게 가려진 고밀도 환경에서는 누락 가능성이 있다.
- 고밀도 군중 전용 모델보다 사람 수를 적게 예측할 가능성이 있다.

## 5. P2PNet 검증

### 5.1 모델 특성

P2PNet은 군중 이미지에서 사람의 머리 위치를 점으로 탐지하는 모델이다.

사람별 위치점을 제공하기 때문에 SAFY의 격자 기반 혼잡도 계산과 기술적으로 연결하기 쉽다. 출력된 점을 이미지 크기로 나누어 정규화하면 기존 `person_centers`와 유사한 입력으로 변환할 수 있다.

공식 저장소:

https://github.com/TencentYoutuResearch/CrowdCounting-P2PNet

### 5.2 실행 과정에서 발견된 호환성 문제

공식 구현은 Python 3.6.5와 PyTorch 1.5.0을 기준으로 작성되어 있다. 현재 SAFY 환경에서 실행하기 위해 다음 호환성 수정이 필요했다.

1. torchvision 버전 판별 방식 수정
   - 기존 코드는 `0.28`을 `0.2`로 잘못 해석했다.
   - 제거된 `_new_empty_tensor`를 가져오려고 하면서 오류가 발생했다.

2. SciPy 의존성 추가
   - 프로젝트 가상환경 전체를 변경하지 않고 실험 복사본의 `vendor` 디렉터리에 격리 설치했다.

3. VGG 초기 가중치 경로 수정
   - 공식 코드에 개발자의 사설 서버 절대 경로가 포함되어 있었다.
   - 최종 P2PNet 체크포인트가 전체 모델 가중치를 포함하므로 별도의 VGG 사전학습 가중치를 불러오지 않도록 수정했다.

4. Pillow API 호환성 수정
   - 제거된 `Image.ANTIALIAS`를 `Image.Resampling.LANCZOS`로 교체했다.

5. 사용자 입력 이미지 지원
   - 원본 데모 코드의 고정 입력 경로를 `--input_path` 인자로 받을 수 있도록 실험 복사본을 수정했다.

이 수정은 모두 `runs/candidate-models/` 아래의 실험 복사본에서 수행했다. 운영 코드나 프로젝트 의존성에는 반영하지 않았다.

### 5.3 실행 결과

#### 공식 고밀도 예제

- ShanghaiTech Part A 가중치로 GPU 추론 성공
- 출력 이미지의 붉은 점이 대부분 사람 머리 위치와 일치
- 고밀도 군중에서 다수의 사람 위치를 탐지할 수 있음을 확인

#### 버스 이미지

- 육안 확인 인원: 4명
- YOLO11n: 4명
- P2PNet: 3명
- 중앙의 사람과 왼쪽 가장자리 사람은 탐지
- 오른쪽 가장자리의 일부만 보이는 사람은 누락

#### COCO 이미지 `000000000257`

- COCO 사람 라벨 수: 13명
- P2PNet 예측 수: 44명
- 출력 이미지에서 다수의 점이 실제로 보이는 사람 머리와 대응

COCO의 객체 탐지 라벨은 군중 계수용 정답이 아니다. 작거나 가려진 사람, 군중 영역이 모두 개별 사람으로 표시되지 않을 수 있다. 따라서 이 이미지에서 P2PNet이 31명을 과대 탐지했다고 단정할 수 없다.

### 5.4 장점

- 고밀도 환경에서 작은 사람의 머리 위치까지 탐지할 가능성이 높다.
- 개별 위치점을 제공해 기존 C·L 격자 계산과 연결할 수 있다.
- 밀집된 영역의 공간적 위치를 확인할 수 있다.

### 5.5 한계

- 현재 프로젝트 환경과 공식 구현의 버전 차이가 크다.
- 운영에 사용하려면 호환성 수정 코드를 별도 어댑터로 관리해야 한다.
- 공식 라이선스가 학술 연구 목적 중심이므로 외부 서비스 적용 전에 사용 범위를 확인해야 한다.
- 희소 인원 이미지에서는 YOLO보다 탐지 결과가 좋지 않을 수 있다.
- 사람 박스를 제공하지 않으므로 YOLO 기반 블러 처리 흐름을 그대로 대체할 수 없다.

## 6. DM-Count 검증

### 6.1 모델 특성

DM-Count는 이미지의 밀도 맵을 생성하고 밀도 값의 합으로 전체 사람 수를 추정한다.

공식 저장소:

https://github.com/cvlab-stonybrook/DM-Count

라이선스는 MIT License다.

### 6.2 실행 과정에서 발견된 호환성 문제

공식 구현은 다음과 같은 오래된 환경을 기준으로 한다.

- PyTorch 1.2.0
- torchvision 0.4.0
- Pillow 6.2.2

현재 프로젝트 환경에서 공식 데모를 그대로 실행하기 어려워 로컬 추론 전용 실험 스크립트를 작성했다.

실험 과정에서 다음과 같이 처리했다.

- 공식 전체 모델 가중치를 직접 로드
- 불필요한 Gradio 및 gdown 의존성을 우회
- 초기 ImageNet VGG19 가중치를 별도로 내려받지 않도록 수정
- 입력 이미지와 출력 경로를 명령행 인자로 지정
- 밀도 맵을 색상 이미지로 저장
- GPU 추론과 처리시간 측정 지원

모델 내부에서 사용 중인 `upsample_bilinear`은 폐기 예정 API 경고가 발생했다. 운영 코드로 사용하려면 `interpolate`로 교체해야 한다.

### 6.3 실행 결과

#### 공식 예제 이미지

- 예측 인원수: 약 181.69명
- 반올림 인원수: 182명
- 처리시간: 약 489ms
- 밀도 맵이 사람 머리가 집중된 영역에 형성됨

#### 버스 이미지

- 육안 확인 인원: 4명
- YOLO11n: 4명
- P2PNet: 3명
- DM-Count: 약 2.03명
- 반올림 인원수: 2명
- 처리시간: 약 290ms

희소 인원 이미지에서는 인원수를 실제보다 적게 예측했다.

#### COCO 이미지 `000000000257`

- COCO 사람 라벨 수: 13명
- DM-Count 예측 수: 약 24.66명
- 반올림 인원수: 25명
- 처리시간: 약 218ms
- 밀도 맵이 실제 사람이 모여 있는 하단 영역을 중심으로 형성됨

COCO 라벨은 군중 계수용 완전한 정답이 아니므로 예측 오차를 확정할 수 없다.

### 6.4 장점

- 고밀도 군중의 전체 인원수를 추정하는 데 적합하다.
- 밀도 맵으로 군중이 집중된 공간을 확인할 수 있다.
- MIT License로 사용 조건이 비교적 명확하다.

### 6.5 한계

- 개별 사람 박스나 중심점을 직접 제공하지 않는다.
- 현재 C·L 계산에 연결하려면 밀도 맵을 8×8 격자로 집계하는 별도 규칙이 필요하다.
- 희소 인원 이미지에서 YOLO보다 정확도가 낮을 수 있다.
- 기존 API의 사람별 신뢰도 및 위치 정보와 출력 구조가 다르다.
- 공식 구현의 의존성 버전이 현재 프로젝트와 크게 다르다.

## 7. COCO 표본 해석 시 주의사항

기존 YOLO 기준 성능 평가에서 사용한 COCO128의 사람 라벨은 객체 탐지용 라벨이다.

군중 계수 데이터셋처럼 이미지에 존재하는 모든 사람 머리를 빠짐없이 표시한 정답이라고 볼 수 없다. 특히 다음 대상은 라벨에서 제외되거나 별도로 표현되지 않을 수 있다.

- 매우 작은 사람
- 심하게 가려진 사람
- 멀리 있는 사람
- 군중 형태로 묶인 영역

따라서 COCO 라벨을 기준으로 계산한 MAE는 COCO 객체 라벨과 YOLO 예측의 차이를 나타낸다. 실제 이미지 전체 인원수에 대한 절대적인 군중 계수 성능으로 해석하지 않는다.

P2PNet과 DM-Count의 정확한 비교에는 다음 중 하나가 필요하다.

- ShanghaiTech
- UCF-QNRF
- NWPU-Crowd
- 모든 사람의 머리를 직접 표시한 SAFY 검증 데이터

## 8. SAFY 적용 판단

### 8.1 현재 MVP 기본 모델

현재 MVP의 기본 모델은 YOLO11n을 유지한다.

이 결정은 YOLO가 모든 상황에서 가장 정확하다는 의미가 아니다. 현재 SAFY 서비스의 입력 범위와 구현 상태를 함께 고려한 결과다.

주요 이유는 다음과 같다.

- 시민 제보에는 빈 화면, 희소 인원, 일반 거리 및 군중 화면이 모두 포함될 수 있다.
- 버스 이미지에서는 YOLO가 실제 인원 4명을 모두 탐지했다.
- 기존 FastAPI 분석 API와 이미 연동되어 있다.
- 사람 수, 박스, 중심점 및 신뢰도를 동시에 제공한다.
- C·L 혼잡도 계산과 디버그 시각화에서 바로 사용할 수 있다.
- 향후 개인정보 블러 처리에 사람 영역 정보를 활용할 수 있다.
- 현재 프로젝트 환경에서 추가 호환성 수정 없이 안정적으로 실행된다.

### 8.2 P2PNet 적용 판단

P2PNet은 고밀도 군중 보완 모델의 우선 후보로 유지한다.

특히 YOLO가 작은 사람을 다수 누락하는 고밀도 화면에서 활용 가능성이 있다. 다만 다음 조건을 먼저 해결해야 한다.

- 학술 연구용 라이선스의 서비스 적용 가능 여부 확인
- 현재 PyTorch 환경에 맞춘 정식 어댑터 구현
- 군중 계수용 완전한 정답 데이터로 정확도 평가
- 모델 전환 기준 정의
- 처리시간 및 GPU 메모리 반복 측정

향후 구조는 다음과 같이 검토할 수 있다.

- 기본 장면: YOLO11n
- 고밀도 장면: P2PNet 추가 분석
- 두 결과가 크게 다른 경우: 낮은 신뢰도 또는 재분석 대상으로 처리

### 8.3 DM-Count 적용 판단

DM-Count는 추가 비교 후보로 보류한다.

고밀도 전체 인원수와 밀도 맵에는 장점이 있지만 기존 SAFY의 사람 중심점 기반 C·L 계산 및 개인정보 처리 흐름과 출력 구조가 다르다.

적용하려면 다음 작업이 추가로 필요하다.

- 밀도 맵을 격자별로 합산하는 C·L 계산 규칙
- 실수 형태의 예측값을 사람 수로 변환하는 반올림 정책
- YOLO 및 P2PNet과 동일한 표본을 이용한 정확도 평가
- 현재 환경에 맞춘 모델 어댑터
- 처리시간 및 GPU 메모리 반복 측정

## 9. 최종 결론

현재 이슈에서의 결정은 다음과 같다.

1. SAFY MVP의 기본 모델은 YOLO11n을 유지한다.
2. P2PNet은 고밀도 군중 보완 모델의 우선 후보로 유지한다.
3. DM-Count는 밀도 맵 기반 대안으로 추가 비교한다.
4. COCO 객체 라벨은 군중 계수의 완전한 정답으로 사용하지 않는다.
5. 모델 교체나 혼합 적용은 군중 계수용 정답 데이터 평가 후 결정한다.
6. 실험 중 수정한 외부 저장소와 모델 가중치는 운영 코드에 포함하지 않는다.

- 외부 모델 저장소 복사본은 `runs/`에만 저장한다.
