# 대표 이미지 전체 블러 처리

## 문서 상태

- 관련 이슈: `S15P11A503-121`
- 블러 규칙 버전: `full-image-blur-v0.1`
- 적용 범위: SAFY 관리자용 대표 이미지
- 처리 방식: 전체 이미지 픽셀화 및 가우시안 블러
- 출력 형식: JPEG

## 역할 분리

영상 프레임 추출과 대표 이미지 선정은 AI 서버가 담당하지 않는다.

- OpenVidu: 영상에서 5초 간격으로 프레임 추출
- 백엔드: 정상 분석 프레임 중 대표 이미지 한 장 선정
- AI 서버: 전달받은 대표 이미지 전체 블러 처리
- 백엔드: 블러 성공 결과만 저장하고 관리자에게 제공
- 프론트엔드: 블러 처리된 대표 이미지만 표시

블러 처리에 실패한 경우 원본 이미지를 대체 결과로 반환하거나
관리자 대표 이미지로 제공하지 않는다.

## API

### 요청

```http
POST /api/v1/privacy/blur
Content-Type: multipart/form-data
```

multipart 필드:

| 필드 | 형식 | 필수 | 설명 |
|---|---|---:|---|
| `image` | 이미지 파일 | O | 블러 처리할 대표 이미지 |

실행 예시:

```bash
curl -X POST \
  "http://127.0.0.1:8000/api/v1/privacy/blur" \
  -F "image=@runs/bus.jpg" \
  --output runs/bus-blurred.jpg
```

## 성공 응답

```http
HTTP/1.1 200 OK
Content-Type: image/jpeg
X-Blur-Rule-Version: full-image-blur-v0.1
X-Image-Width: 810
X-Image-Height: 1080
X-Processing-Time-Ms: 12
```

응답 본문은 블러 처리된 JPEG 이미지 바이트다.

응답 헤더:

| 헤더 | 의미 |
|---|---|
| `X-Blur-Rule-Version` | 적용된 블러 규칙 버전 |
| `X-Image-Width` | 출력 이미지 너비 |
| `X-Image-Height` | 출력 이미지 높이 |
| `X-Processing-Time-Ms` | AI 내부 블러 처리시간 |

출력 이미지의 너비와 높이는 입력 이미지와 동일하게 유지한다.

## 실패 응답

실패 응답은 원본 이미지나 내부 예외 메시지를 포함하지 않는다.

```json
{
  "failureCodes": [
    "IMAGE_DECODE_FAILED"
  ]
}
```

상태 코드와 실패 코드:

| HTTP 상태 | 실패 코드 | 의미 |
|---:|---|---|
| `400` | `EMPTY_IMAGE` | 업로드된 이미지가 비어 있음 |
| `415` | `UNSUPPORTED_MEDIA_TYPE` | 이미지가 아닌 형식이 전달됨 |
| `422` | `IMAGE_DECODE_FAILED` | 이미지 바이트를 디코딩할 수 없음 |
| `500` | `IMAGE_BLUR_FAILED` | 전체 블러 연산 실패 |
| `500` | `IMAGE_ENCODING_FAILED` | JPEG 결과 인코딩 실패 |

내부 예외 메시지와 스택 트레이스는 서버 로그에서만 확인한다.

## 블러 처리 규칙

`full-image-blur-v0.1`은 다음 순서로 이미지를 처리한다.

1. 입력 이미지 바이트를 OpenCV 이미지로 디코딩한다.
2. 이미지 너비와 높이를 각각 10% 크기로 축소한다.
3. 축소 이미지를 원본 크기로 다시 확대해 세부 정보를 제거한다.
4. 이미지 크기에 비례한 가우시안 블러를 전체 영역에 적용한다.
5. JPEG 품질 85로 결과 이미지를 인코딩한다.

계산 기준:

```text
reducedWidth = max(1, round(width × 0.10))
reducedHeight = max(1, round(height × 0.10))
blurSigma = max(3.0, min(width, height) × 0.02)
```

사람이나 얼굴 영역만 선택하지 않고 이미지 전체에 동일한 처리를 적용한다.

## 보안 원칙

- 블러 실패 시 입력 원본을 결과로 반환하지 않는다.
- 오류 응답에 원본 이미지 바이트를 포함하지 않는다.
- 오류 응답에 내부 예외 메시지를 포함하지 않는다.
- AI 서버는 블러 처리 과정에서 이미지를 별도 파일로 저장하지 않는다.
- OpenCV 재인코딩을 통해 입력 이미지의 EXIF 메타데이터를 출력에 복사하지 않는다.
- Git에는 원본 대표 이미지와 블러 결과 이미지를 포함하지 않는다.

## 검증 항목

자동 테스트에서 다음 내용을 확인한다.

- 출력 이미지 크기가 입력 이미지 크기와 동일함
- 출력 이미지가 입력 이미지 바이트와 다름
- 이미지의 고주파 세부 정보가 크게 감소함
- 빈 파일이 `EMPTY_IMAGE`로 거부됨
- 이미지가 아닌 형식이 `UNSUPPORTED_MEDIA_TYPE`으로 거부됨
- 손상된 이미지가 `IMAGE_DECODE_FAILED`로 처리됨
- 블러 처리 실패가 `IMAGE_BLUR_FAILED`로 처리됨
- 실패 응답에 원본과 내부 예외가 노출되지 않음
- 실제 대표 표본에서 얼굴과 글자는 식별할 수 없음
- 사람의 대략적인 위치와 현장 상황은 확인할 수 있음

## 현재 한계

전체 블러는 개인정보 식별 위험을 크게 낮추기 위한 MVP 처리다.

블러 강도가 모든 이미지에서 법적·기술적 비식별성을 절대적으로
보장하는 것은 아니다. 실제 SAFY 촬영 이미지에서 관리자 화면 크기와
확대 가능 여부를 함께 검증하고 필요하면 픽셀화 비율과 블러 강도를
후속 버전에서 조정한다.

## 대표 프레임 선정 주체

대표 프레임은 AI 서버가 아니라 백엔드가 선정한다.

AI 서버의 프레임 분석 API는 전달받은 프레임 한 장만 독립적으로
분석한다. 따라서 AI 서버는 다음 정보를 알 수 없다.

- 해당 제보에서 추출된 전체 프레임 수
- 이전·다음 프레임의 분석 결과
- 모든 프레임 분석이 완료되었는지 여부
- 전체 프레임 중 어떤 프레임의 혼잡도가 가장 높은지

백엔드는 제보 ID와 추출 프레임 ID를 기준으로 모든 분석 결과를
수집할 수 있으므로, 프레임 간 결과를 비교해 대표 프레임을 선정한다.

AI 서버는 제보별 분석 상태를 보관하지 않는 stateless 구조를 유지한다.

## 대표 프레임 후보

대표 프레임 후보에는 `analysisStatus`가 `COMPLETED`인 프레임만
포함한다.

다음 프레임은 대표 프레임 후보에서 제외한다.

- `INVALID_FRAME`
- `FAILED`
- 이미지 분석 결과가 누락된 프레임
- 블러 처리에 사용할 원본 프레임을 조회할 수 없는 경우

`INVALID_FRAME`과 `FAILED` 프레임의 `personCount`, C, L을 0으로
간주해서는 안 된다. 해당 프레임은 분석에 성공하지 못한 것이므로
대표 프레임 선정 계산에서 제외한다.

## 대표 프레임 선정 기준

백엔드는 정상 분석된 프레임을 다음 순서로 비교한다.

1. `localPeakCongestionScore`가 가장 높은 프레임을 선택한다.
2. `localPeakCongestionScore`가 같으면 `personCount`가 더 높은
   프레임을 선택한다.
3. `personCount`도 같으면 `visualCongestionScore`가 더 높은
   프레임을 선택한다.
4. 모든 값이 같으면 영상에서 먼저 추출된 프레임을 선택한다.

정렬 기준은 다음과 같다.

| 우선순위 | 필드 | 정렬 방향 |
|---:|---|---|
| 1 | `localPeakCongestionScore` | 내림차순 |
| 2 | `personCount` | 내림차순 |
| 3 | `visualCongestionScore` | 내림차순 |
| 4 | 프레임 추출 시각 또는 프레임 순번 | 오름차순 |

`localPeakCongestionScore`를 첫 번째 기준으로 사용하는 이유는
영상 전체에서 가장 혼잡한 순간을 관리자에게 대표 이미지로
제공하기 위해서다.

## 정상 프레임이 없는 경우

제보 영상에서 `COMPLETED` 프레임이 한 장도 없으면 대표 프레임을
선정하지 않는다.

이 경우 백엔드는 다음과 같이 처리한다.

- AI 블러 API를 호출하지 않는다.
- 원본 프레임을 대표 이미지로 대신 사용하지 않는다.
- 관리자 화면에는 대표 이미지가 없거나 생성할 수 없다는 상태를
  제공한다.
- 프레임별 `INVALID_FRAME` 및 `FAILED` 기록은 그대로 유지한다.

## 대표 이미지 생성 흐름

전체 처리 흐름은 다음과 같다.

1. OpenVidu 측에서 제보 영상의 프레임을 5초 간격으로 추출한다.
2. 추출된 각 프레임을 AI 프레임 분석 API로 전달한다.
3. AI 서버는 프레임마다 분석 상태, 사람 수, C, L을 반환한다.
4. 백엔드는 프레임별 분석 결과를 제보와 연결해 저장한다.
5. 백엔드는 `COMPLETED` 프레임만 대표 프레임 후보로 사용한다.
6. 백엔드는 대표 프레임 선정 기준에 따라 한 장을 선택한다.
7. 백엔드는 선택한 원본 프레임을 AI 블러 API로 전달한다.
8. AI 서버는 이미지 전체를 블러 처리해 JPEG 바이트로 반환한다.
9. 백엔드는 블러 성공 결과만 대표 이미지로 저장한다.
10. 관리자 화면에는 블러 처리된 대표 이미지만 제공한다.

## 블러 실패 처리

대표 프레임 선정에 성공했더라도 블러 처리에 실패할 수 있다.

블러 처리에 실패하면 다음 원칙을 적용한다.

- 원본 프레임을 블러 결과 대신 저장하지 않는다.
- 원본 프레임을 관리자 화면에 제공하지 않는다.
- 실패 코드를 백엔드 로그 또는 처리 상태에 기록한다.
- 재시도 여부와 횟수는 백엔드 정책에서 결정한다.
- 재시도 후에도 실패하면 대표 이미지는 생성 실패 상태로 처리한다.

블러 실패는 기존 프레임 분석 결과를 변경하지 않는다. 해당 프레임의
`analysisStatus`는 계속 `COMPLETED`이며, 대표 이미지 생성 상태만
별도로 실패 처리한다.

## 백엔드 구현 시 필요한 데이터

백엔드가 대표 프레임을 선정하려면 프레임별로 최소한 다음 정보가
필요하다.

| 데이터 | 용도 |
|---|---|
| 제보 ID | 같은 영상에서 나온 프레임을 그룹화 |
| 추출 프레임 ID | 원본 프레임 식별 |
| 프레임 추출 시각 또는 순번 | 최종 동점 처리 |
| `analysisStatus` | 대표 프레임 후보 필터링 |
| `personCount` | 두 번째 선정 기준 |
| `visualCongestionScore` | 세 번째 선정 기준 |
| `localPeakCongestionScore` | 첫 번째 선정 기준 |
| 원본 프레임 접근 정보 | 선정 후 AI 블러 API 호출 |

대표 프레임 선정과 블러 결과 저장을 담당하는 백엔드 구현 범위는
`S15P11A503-126`에서 관리한다.
