# AI 프레임 분석 런타임 성능 측정

## 문서 상태

- 관련 이슈: `S15P11A503-99`
- 상위 스토리: `S15P11A503-64`
- 대상 모델: YOLO11n
- 측정 범위: FastAPI 단일 프레임 분석 전체 경로
- 측정 방식: 단일 요청 및 순차 연속 프레임
- 상태: SAFY MVP 1차 운영 기준

## 측정 목적

영상에서 5초 간격으로 추출한 프레임을 AI 서버가 처리할 때 다음 항목을 확인한다.

- 첫 요청 지연시간
- 워밍업 이후 평균 지연시간
- 중앙값 지연시간
- P95 지연시간
- 최대 지연시간
- 초당 순차 처리 프레임 수
- 최대 GPU 할당 메모리
- 정상·품질 불량·실패 처리 건수

동시에 여러 제보가 유입되는 부하 테스트는 이 문서의 범위가 아니다. 동시 요청과 전체 시스템 수용 범위는 인프라 이슈에서 별도로 측정한다.

## 측정 대상 경로

측정 스크립트는 FastAPI 테스트 클라이언트를 이용해 실제 프레임 분석 엔드포인트를 호출한다.

```text
이미지 파일 읽기
→ POST /api/v1/analyze/frame
→ 프레임 품질 검사
→ YOLO 사람 탐지
→ C·L 혼잡도 계산
→ FrameAnalysisResponse 생성
```

따라서 순수 YOLO 추론시간뿐 아니라 AI API 내부의 품질 검사, 후처리 및 응답 생성 시간이 포함된다.

외부 네트워크 전송시간, 백엔드 저장시간 및 OpenVidu 프레임 추출시간은 포함하지 않는다.

## 측정 지표

### 단일 요청 지연시간

새 프로세스에서 첫 프레임 요청을 처리하는 데 걸린 시간이다.

첫 요청에는 다음 준비 비용이 포함될 수 있다.

- YOLO 모델 로딩
- 모델 가중치 로딩
- CUDA 컨텍스트 준비
- GPU 메모리 할당
- 운영체제 파일 캐시 상태

따라서 첫 요청은 워밍업 이후 요청보다 느리며 실행 환경과 캐시 상태에 따라 편차가 크다.

### 평균 지연시간

워밍업 이후 측정한 모든 프레임 처리시간의 평균이다.

```text
meanLatencyMs
= 전체 프레임 지연시간 합계 / 측정 프레임 수
```

### P95 지연시간

전체 프레임 중 약 95%가 이 시간 이내에 완료된다는 의미다.

평균값만으로는 일부 느린 요청을 확인하기 어려우므로 운영 기준에서는 평균과 P95를 함께 확인한다.

### 순차 처리량

한 요청씩 순서대로 처리했을 때 초당 완료한 프레임 수다.

```text
throughputFps
= 전체 측정 프레임 수 / 전체 측정시간(초)
```

이 값은 동시에 처리할 수 있는 제보 영상 수와 동일하지 않다. 동시 요청에서는 GPU 경합, API 대기열, 네트워크 및 백엔드 부하가 추가된다.

### GPU 메모리

PyTorch의 `max_memory_allocated()`를 사용해 측정 구간의 최대 GPU 할당 메모리를 기록한다.

```text
peakGpuMemoryMb
```

이 값은 GPU 전체 사용률 백분율이 아니라 PyTorch가 할당한 최대 GPU 메모리다.

## 워밍업 기준

연속 프레임 성능 측정 전 동일 프레임을 3회 분석한다.

```text
warmupIterations = 3
```

워밍업 요청은 FPS와 지연시간 통계에서 제외한다. 워밍업이 끝난 다음 GPU 최대 메모리 기록을 초기화하고 본 측정을 시작한다.

운영 환경에서도 서버 시작 후 준비 요청을 수행해 실제 사용자 요청이 모델 초기화 비용을 부담하지 않도록 하는 방식을 권장한다.

다만 고밀도 표본에서도 P95는 약 30ms, 순차 처리량은 약 46 FPS로 측정됐다.

## 5초 프레임 간격과의 관계

제보 영상 한 개에서 5초마다 프레임 한 장을 추출하면 영상 한 개가 생성하는 평균 요청률은 다음과 같다.

```text
1 frame / 5 seconds = 0.2 FPS
```

현재 순차 GPU 측정 결과는 단일 스트림의 5초 처리 간격보다 충분히 빠르다.

그러나 측정 FPS를 `0.2`로 단순히 나눠 동시 수용 영상 수로 사용하지 않는다. 실제 동시 처리 한계에는 다음 요소가 영향을 준다.

- 여러 요청의 동시 도착
- GPU 작업 경합
- API 요청 대기열
- 이미지 업로드 네트워크
- 백엔드 저장 처리
- OpenVidu Egress 및 프레임 추출 부하
- 장시간 실행 시 발열과 GPU 클럭 변화

동시 제보 수용 범위는 별도 부하 테스트 결과로 결정한다.

## SAFY MVP 1차 운영 기준

워밍업 이후 순차 프레임 분석에 다음 기준을 적용한다.

| 지표 | 1차 기준 |
|---|---:|
| 평균 지연시간 | 50ms 이하 |
| P95 지연시간 | 100ms 이하 |
| 순차 처리량 | 20 FPS 이상 |
| 최대 GPU 할당 메모리 | 512MB 이하 |
| 고정 검증 표본의 FAILED | 0건 |

현재 대표 표본과 고밀도 표본은 위 기준을 모두 통과했다.

이 기준은 성능 저하를 발견하기 위한 1차 회귀 기준이며, 서비스 전체의 최종 SLA가 아니다.

## 첫 요청 처리 기준

측정 과정에서 첫 요청 지연시간은 약 1.6초에서 5.1초 사이로 관찰됐다. 운영체제 파일 캐시와 CUDA 초기화 상태에 따른 편차가 크므로 첫 요청 지연시간을 워밍업 이후 처리 SLA와 합치지 않는다.

현재 결정은 다음과 같다.

```text
AI 서버 시작
→ 모델 준비
→ 워밍업 요청 수행
→ 준비 완료 후 실제 분석 요청 수신
```

서버 시작 직후 워밍업 실패 여부와 준비 상태 확인 방식은 배포 담당자와 합의가 필요하다.

## 보고서 저장

측정 결과 JSON은 `runs/` 아래에 저장하며 Git에 포함하지 않는다.

보고서에는 다음 정보가 포함된다.

- 모델 이름과 버전
- Python 버전
- PyTorch 버전
- CUDA Runtime 버전
- GPU 이름과 전체 메모리
- 워밍업 횟수
- 단일 요청 결과
- 연속 프레임 결과
- 상태별 처리 건수
- 평균·중앙값·P95·최대 지연시간
- FPS
- 최대 GPU 할당 메모리

## 보안 및 저장 원칙

- 원본 검증 이미지는 Git에 포함하지 않는다.
- 생성된 성능 JSON 보고서는 `runs/`에만 저장한다.
- 모델 가중치는 Git에 포함하지 않는다.
- 개인정보가 포함된 실제 제보 프레임을 성능 표본으로 커밋하지 않는다.
- 측정 결과에는 이미지 원본이나 실제 예외 메시지를 기록하지 않는다.

## 현재 한계

- 현재 측정은 RTX 4050 Laptop GPU 한 대에서 수행했다.
- 외부 네트워크 지연시간은 포함하지 않았다.
- 백엔드 DB 저장시간은 포함하지 않았다.
- OpenVidu 프레임 추출시간은 포함하지 않았다.
- 동시 요청 부하는 측정하지 않았다.
- 장시간 지속 부하에 따른 발열과 스로틀링은 측정하지 않았다.
- CPU 전용 배포 환경은 측정하지 않았다.
- GPU 전체 사용률 백분율은 측정하지 않고 최대 할당 메모리만 기록했다.

## 후속 작업

- 최종 배포 장비에서 동일 스크립트 재실행
- 서버 시작 시 모델 워밍업 적용 여부 결정
- 동시 요청 부하 테스트
- 백엔드 저장과 OpenVidu를 포함한 E2E 지연시간 측정
- 장시간 지속 부하와 GPU 발열 확인
- 운영 모니터링 지표 및 경고 기준 결정
