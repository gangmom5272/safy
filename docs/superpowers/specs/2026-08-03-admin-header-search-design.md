# 관리자 홈 헤더 검색창 설계

## 목표

관리자 홈 화면의 기존 헤더 우측에 전역 검색창 형태의 UI를 추가한다. 현재 프로젝트에는 관리자 전역 검색 API와 검색 결과 경로가 없으므로 이번 변경은 검색 입력과 제출 인터랙션까지만 제공하며, 실제 검색 기능을 새로 만들거나 기존 제보 목록 검색으로 우회 연결하지 않는다.

## 범위

- 홈 화면(`/dashboard`)에서만 긴급 위험 알림 버튼 왼쪽에 검색창을 표시한다.
- 기존 홈 제목, 서울 기준 시각, 마지막 대시보드 갱신 표시와 긴급 위험 알림 동작을 유지한다.
- 다른 관리자 페이지의 헤더, 사이드바, 대시보드 본문, API 및 라우터는 변경하지 않는다.
- 요청에서 제외된 `LIVE` 배지는 컴포넌트와 스타일 모두 추가하지 않는다.

## UI 구조

- 검색창은 `<form role="search">`으로 구성한다.
- 왼쪽 검색 아이콘은 새 라이브러리 없이 기존 프로젝트 방식과 같은 인라인 SVG를 사용한다.
- 입력 placeholder는 `전체 검색 (지역 · 제보 ID · 담당자)`로 표시한다.
- 검색창은 기존 밝은 관리자 헤더에 어울리는 옅은 회색 배경과 테두리, 둥근 모서리를 사용한다.
- 데스크톱에서 약 280~360px 범위의 너비를 확보하고, 화면이 좁아지면 검색창이 먼저 축소되도록 한다.
- 검색 버튼에는 `전체 검색 실행` 접근성 이름을 제공한다.

## 입력 및 제출 동작

- 입력값은 `AdminHeader` 내부의 제어 상태로 관리한다.
- Enter 키와 검색 아이콘 버튼이 동일한 form 제출 경로를 사용한다.
- 제출 시 앞뒤 공백을 제거하고, 공백 제거 후 빈 값이면 아무 동작도 하지 않는다.
- 유효한 검색어 제출 시에도 아직 페이지 이동이나 API 요청은 하지 않는다.
- 실제 연결 위치에는 `// TODO: 관리자 전체 검색 API 또는 검색 결과 페이지와 연결` 주석을 남긴다.

기존 제보 목록의 검색은 제보 데이터에 한정되어 있고 전역 담당자 검색을 보장하지 않는다. 이를 전역 검색창에 연결하면 UI가 약속하는 범위와 실제 동작이 달라지므로 재사용하지 않는다.

## 반응형 동작

- 기존 사이드바 너비와 데스크톱 헤더 높이 `83px`을 유지한다.
- 우측 영역은 검색창과 긴급 알림 버튼을 한 행에 유지하되 검색창이 우선 축소된다.
- 모바일에서는 기존 헤더의 줄바꿈 구조 안에서 검색창이 사용 가능한 너비를 차지한다.
- 기존의 마지막 갱신 정보 숨김 규칙과 긴급 알림 버튼 노출 우선순위를 유지한다.
- 가로 스크롤이 발생하지 않도록 입력 요소에 최소 너비 제한을 적용한다.

## 오류 및 상태 처리

- 별도 로딩, 오류 또는 검색 결과 상태를 만들지 않는다.
- 빈 검색 제출은 조용히 무시한다.
- 검색어가 유효하더라도 아직 외부 상태를 변경하지 않는다.

## 검증

- 홈 화면에서 검색창이 긴급 알림 버튼 왼쪽에 표시되는지 확인한다.
- 다른 관리자 페이지에는 검색창이 표시되지 않는지 확인한다.
- 입력, Enter 제출, 아이콘 제출 및 공백 입력 방지가 정상인지 확인한다.
- 기존 긴급 알림 모달, 시간 갱신, 사이드바와 대시보드 본문이 유지되는지 확인한다.
- 데스크톱과 모바일 화면에서 가로 넘침이 없는지 브라우저로 확인한다.
- `npm run lint`와 `npm run build`를 실행한다.
