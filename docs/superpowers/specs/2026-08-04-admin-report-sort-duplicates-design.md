# 관리자 제보 정렬 중복 표시 수정 설계

## 문제

관리자 제보 목록에는 실제로 6개의 배정 이력이 있지만 정렬 탭을 반복해서 누르면 테이블 행이 8개, 11개처럼 늘어난다. 화면의 `총 6건` 표시는 그대로이므로 API 응답이나 프론트 상태 배열이 증가한 문제가 아니라 React DOM 재조정 과정의 표시 오류다.

## 원인

같은 제보가 재배정되면 서로 다른 배정 이력이 같은 `reportId`를 가질 수 있다. API는 각 이력을 구분하는 고유한 `assignmentId`도 제공하지만, 목록 행은 현재 `report.id`만 React `key`로 사용한다. 같은 키를 가진 행들이 정렬로 위치를 바꾸면 React가 행을 정확히 식별하지 못해 기존 DOM 행을 잘못 재사용한다.

## 수정 설계

- 담당 이력 행은 `assignmentId`를 React 키로 사용한다.
- 목 데이터처럼 `assignmentId`가 없는 제보는 기존 `report.id`를 예비 키로 사용한다.
- API 조회, 필터, 정렬 비교 함수, 화면 디자인은 변경하지 않는다.
- 같은 제보의 서로 다른 배정 이력은 삭제하거나 합치지 않는다. 최초 6개 행은 그대로 유지되고 정렬 시 순서만 바뀐다.

## 검증

- 같은 `reportId`와 서로 다른 `assignmentId`를 가진 두 행의 키가 서로 다름을 Node 내장 테스트로 검증한다.
- `assignmentId`가 없는 목 데이터는 `report.id`로 안정적으로 식별되는지 검증한다.
- 관리자 프론트엔드의 테스트, 린트, 빌드를 실행한다.
- 실제 화면에서 네 정렬 탭을 반복 전환해 행 개수가 계속 6개인지 확인한다.

## 범위 제외

- 동일 제보의 배정 이력 통합 또는 제거
- 서버 정렬 및 API 응답 구조 변경
- 제보 목록 디자인 변경
