# SAFY 관리자 페이지 5차 UI 수정 설계

## 목표와 범위

관리자 페이지의 제보 목록과 실시간 모니터링 필터 배치를 개선한다. 기존 SAFY Admin의 색상, 폰트, 버튼, 여백, API 호환 상태 구조와 WebRTC 동작은 유지한다. 사용자 프론트엔드, 백엔드, 제보 테이블, 모니터링 영상 카드는 변경하지 않는다.

## 제보 목록

기본 필터 줄은 검색 아이콘이 있는 통합 검색창과 `상세조건` 토글 버튼으로 구성한다. 검색어는 제보 ID, 내용, 제보자명, 주소, 지역명 중 하나라도 일치하면 결과에 포함한다. Enter와 `필터 적용`은 동일한 기존 적용 흐름을 사용한다.

상세조건은 기본적으로 닫혀 있으며 토글해도 입력값을 유지한다. 열린 상태에서만 닫기 아이콘을 표시하고 `aria-expanded`, `aria-controls`, 상태별 `aria-label`을 제공한다. 상세조건은 제보일, 카테고리, 위험도, AI 분석 상태, 정렬 순으로 배치한다. 처리 상태는 UI에서 제외하지만 관련 타입과 기존 데이터 구조는 삭제하지 않는다.

제보일은 하나의 외곽 영역 안에 시작 날짜와 종료 날짜를 배치해 날짜 범위 컨트롤처럼 표현한다. 표시와 상태 변경은 하나의 필터 단위로 취급하되 내부의 `startDate`와 `endDate` 값은 유지하여 기존 필터 처리 및 향후 API 형식과 호환한다.

새로고침과 필터 적용 버튼은 상세조건의 열림 여부와 관계없이 필터 아래 오른쪽에 둔다. 구분선은 두 버튼 아래, 목록 콘텐츠 위에 위치한다. 새로고침은 기존 초기화 동작, 필터 적용은 기존 적용 동작을 유지한다.

## 실시간 모니터링

콘텐츠 영역의 중복 제목과 필터를 감싸는 카드 배경을 제거한다. 지역, 위험도, 연결 상태 라벨도 제거하고 컨트롤을 한 줄에 둔다.

왼쪽 필터 그룹은 지역 검색 2.4, 위험도 1, 연결 상태 1 비율을 사용하며 초기화 버튼을 같은 줄에 배치한다. 지역 검색창에는 새 의존성 없이 기존 인라인 SVG 패턴으로 위치 아이콘을 넣는다. 위험도와 연결 상태의 초기 표시 문구는 `선택`으로 바꾸되 `전체` 옵션과 전체 조회 동작은 유지한다.

오른쪽에는 기존 2x2, 3x3, 5x5 선택 상태와 목록 배치 로직을 사용하는 작은 segmented control을 배치한다. 화면이 좁아지면 필터 그룹과 segmented control이 자연스럽게 줄바꿈된다.

## 상태와 데이터 흐름

제보 목록은 draft 필터와 적용된 필터를 구분하는 기존 패턴을 유지한다. 통합 검색값은 단일 `keyword`로 관리하고 로컬 필터링 시 기존 검색 대상과 지역 대상을 OR 조건으로 검사한다. 상세조건 토글은 별도 UI 상태만 변경한다.

모니터링은 기존 지역, 위험도, 연결 상태, 그리드 크기 상태 및 실시간 연결 흐름을 변경하지 않는다. Select의 기본 표시만 placeholder 역할의 빈 값으로 구분하고, 사용자가 `전체`를 선택하면 기존 전체 필터 값으로 처리한다.

## 오류 및 접근성 처리

기존 빈 결과와 연결 오류 처리를 유지한다. 날짜 범위에서 시작일이 종료일보다 늦은 경우 현재 필터 결과가 비게 되는 기존 비교 동작을 유지하며 별도 검증 기능은 추가하지 않는다. 아이콘은 장식용일 경우 접근성 트리에서 숨기고, 토글과 아이콘 버튼에는 명확한 레이블을 제공한다.

## 검증 기준

- `npm run lint`와 `npm run build`가 성공한다.
- 통합 검색이 일반 검색 대상과 주소·지역명을 OR 조건으로 검색한다.
- Enter와 필터 적용이 동일한 결과를 만들고 새로고침이 초기화한다.
- 상세조건을 닫았다 열어도 입력값이 유지된다.
- 시작·종료 날짜, 카테고리, 위험도, AI 분석 상태, 정렬이 기존 결과에 반영된다.
- 모니터링 필터, 초기화, 2x2·3x3·5x5 전환이 기존처럼 동작한다.
- 브라우저 콘솔 오류가 없고 기존 모니터링 연결 및 상세 화면 진입이 유지된다.
